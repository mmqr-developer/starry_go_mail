Pretty Good Privacy

Keys pasted below are parsed when you save, so a malformed block is refused while you are looking at it. With a private key stored and PGP switched on, the composer gains Sign and Encrypt, and signed or encrypted mail you receive is verified and decrypted as you read it. The wire format is PGP/MIME (RFC 3156), which protects the whole message rather than just a plain-text body.

Encrypting needs a key for every recipient, kept on their entry in Contacts — a send is refused, by name, if one of them has none, rather than quietly leaving that person out. Your own public key is used too, so the copy filed in Sent is one you can still read.

What is deliberately not here: no keyservers and no web of trust. A key is trusted because it is on a contact, and the fingerprint shown beside it is what you compare against what its owner told you. Nothing else binds a key to a person.

How OpenPGP works, briefly

PGP is hybrid cryptography: asymmetric keys to agree on a secret, symmetric cryptography to move the actual bytes.

Every participant holds a key pair. The public half is handed out freely; the private half never leaves its owner and is normally protected by a passphrase, so the file on disk is useless on its own.

To encrypt a message, the sender generates a random session key and encrypts the message body with it symmetrically — AES-256 in practice, because asymmetric operations are far too slow for a message of any size. That session key is then encrypted once per recipient using each recipient's public key, and those small blobs travel with the message. Each recipient decrypts the session key with their private key, then decrypts the body with it. This is why adding a recipient does not re-encrypt the body: only the session key is re-wrapped.

To sign, the sender hashes the message (SHA-256 or better) and encrypts that digest with their private key. Anyone with the sender's public key can decrypt the digest and compare it with their own hash of the message. A match proves two separate things: the message was not altered, and it was signed by the holder of that private key. Signing and encrypting are independent — a message can be either, both, or neither.

The output is binary, so email carries it in ASCII armour: the base64 blocks below, wrapped in BEGIN/END lines with a CRC. In mail this appears either inline (RFC 4880 clearsigned text) or as PGP/MIME parts (RFC 3156), which is the form that survives HTML and attachments.

The hard problem is not the mathematics, it is knowing whose key is whose. A public key proves only that whoever holds the matching private key produced the signature — not who that is. That binding comes from outside: comparing fingerprints over a channel an attacker does not control, the web of trust, or a keyserver you have decided to believe. This app shows the fingerprint of each stored key for exactly that comparison.

One Time Password

A TOTP — time-based one-time password — is the six digits an authenticator app shows and replaces every thirty seconds. Setting it up shares one secret between this server and your phone; from then on both sides compute the same code from that secret and the current time, so nothing travels between them and a code that has been used, seen or written down is worthless within half a minute.

It is a second factor, not a replacement for the password: signing in asks for both. What it defends against is a password that has leaked — reused on another site, guessed, or read over a shoulder — because knowing it is no longer enough on its own.
