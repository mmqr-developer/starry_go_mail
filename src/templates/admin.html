Not built

There is no contacts feature in this client, so there is nothing here to configure. The original's screen sets a storage backend (PDO/SQLite), CardDAV sync and a suggestions limit.

Building it would mean: a contacts table keyed by application account, an autocomplete on the compose screen's To/Cc fields, and — if sync is wanted — a CardDAV client. The storage question is already answered here: it would go in the same SQLite database as everything else, so the original's Storage section has no equivalent.

Controls are deliberately absent rather than shown and inert. See NOTES.md.

{{end}} {{define "admin-extensions"}}

Not built

This client has no plugin system. The original loads PHP extensions from a directory and lists them here with enable/disable and per-extension configuration.

A Go binary cannot load plugins the way an interpreted app can — the realistic equivalents are compile-time registration, or out-of-process hooks over HTTP. Neither is worth building before there is a second thing that wants one.

Controls are deliberately absent rather than shown and inert. See NOTES.md.
